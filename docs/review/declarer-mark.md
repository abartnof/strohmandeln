## Confirmed

- **kit change (2).** `hud.mark(side, spec)` defaults to no mark; `drawName` with no mark sets the name alone, so a consumer that never calls it renders the same text as before. Cassino has its own vendored kit copy (kit/ here is the copy from Cassino's commit 73f0cd7), so nothing there changes; no other kit consumer exists in this repo (only `web3d/src/main.js` imports `createHud`). `modules.test.js` and `build.py --check` pass. Policy gap is finding 2 only.
- **Lifetime (3).** `declarerMark` is null until `model.declarer` is set; `declarer.test.js` shows the mark goes at the next `deal_start` and a simple game never has one (checked in the browser as well). Restore mid-deal: the mark shows after "Continue". Language switch rebuilds the HUD; the mark returns (the key includes the title). `hud.reset` keeps marks by design (tested).
- **Aria / focus (4).** The span is `tabindex=0`, `role=note`, with `aria-label`; focus ring visible; the bubble is `pointer-events: none`. `title` plus `aria-label` duplicates the text for some readers (finding 3).
- **Tests (7).** `kit/test/hud.test.js` and `web3d/test/declarer.test.js` are meaningful (they fail without the code: names, tooltip, reset, clearing, the bid-to-next-deal lifetime over a played sitting, no mark in a simple game). The browser check covers the take-up, the simple game, Tab reachability, the focus bubble and the dealer's word. Gaps in finding 6.
- **TABLE3D.** 2.5.8 and the `deal_start`, `bid`, 4.3.1 and browser-check edits match the code and are terse.
